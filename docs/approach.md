# 从问题到可追溯的学习记录

## 原文先行

先确认讨论对象属于哪个版本、哪一段、哪一个公式或图表。解释可以补充直觉和例子，但原文结论、教学构造和推断应能区分。

## 按主题连续组织

围绕一个机制连续说明它解决的问题、输入输出、关键步骤和成立条件。图、形状、代码和数学关系组织在相同主题内，避免把它们拆成互不衔接的材料。

## 小实验承担有限目标

小实验用来检查局部机制，例如输入输出形状、训练与推理的不同角色，或扩散过程中的数值关系。结果同时记录范围和限制，不把一个局部程序跑通写成整个模型已经复现。

## 反馈决定下一步

独立作答或口头解释提供理解证据。措辞问题可以短纠正，阻塞后续理解的核心误解需要补讲；如果教材本身不清楚，先修教材。学习者切换论文时保留旧任务状态，不强行宣称上一阶段已经通过。

## 文件承担长期记忆

讲义、问答、实验记录、作答和进度分别管理，通过来源或任务标识关联。聊天承担讨论，重要内容落入对应文件；同一问题的追问扩充原条目，避免复制出多个互相冲突的答案。

本页介绍协作方法；项目 skill 与脚本见[开源仓库](https://github.com/by-lastime/research-learning-workflow)。个人学习记录未公开。
